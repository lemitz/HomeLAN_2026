# 🏠 HomeLAN Messenger v0.5.0 Release Candidate

**Компактный приватный self-hosted мессенджер для закрытой локальной сети (LAN)**

---

## ⚡ О проекте

**HomeLAN Messenger** — это защищенный LAN-мессенджер, предназначенный для автономной работы в закрытой домашней локальной сети без подключения к интернету, внешним серверам или облакам.

Система строго ориентирована на **2 пользователей** и **до 4 личных устройств** (Windows-клиент на ПК и Android-клиент на смартфонах). Она оптимизирована для экономичного использования ресурсов на серверах типа **Orange Pi Zero 3** (2GB RAM) и любых локальных Linux/Windows-машинах.

## 🛡️ Безопасность и архитектурные решения (v0.5.0 RC)

* **Сквозное E2E-шифрование:** Содержимое сообщений и файлов шифруется непосредственно на устройствах пользователей по стандарту **ChaCha20-Poly1305** (с 12-байтовым случайным nonce) на основе общего секрета, выработанного по протоколу **ECDH X25519**.
* **Сессионная авторизация:** Сервер генерирует криптографически случайные 32-байтовые сессионные токены, сохраняя на диске исключительно их безопасные **SHA-256 хэши**. Токены строго привязаны к связке `user_id` и `device_id` и проверяются на уровне всех защищенных эндпоинтов и WebSocket соединения.
* **Аппаратный USB-ключ (USB Master Key):** Сервер проверяет наличие USB-флешки каждую секунду (с защитой от сбоев/дребезга питания через 3 быстрых повтора по 50 мс). При физическом отключении флешки запускается экстренное уничтожение базы данных.
* **Пароль принуждения (Duress Password):** При вводе специального пароля на экране входа сервер имитирует ошибку авторизации `401 Unauthorized`, а в фоновом потоке запускает необратимый экстренный вайп.
* **Защита от OOM и переполнения диска:** Файлы загружаются через потоковый стриминг с ограничением буфера RAM до 32 МБ и проверкой свободного пространства на диске перед записью.
* **Синхронизация часов в LAN (Time Delta Sync):** Алгоритм клиентской калибровки времени позволяет компенсировать дрифт системных часов на устройствах без использования внешних NTP-серверов.
* **Безопасное хранилище на клиенте:** Приватные ключи шифрования и сессионные токены перенесены из SharedPreferences в системное безопасное хранилище (**Android Keystore / Windows DPAPI**).

## ⚡ Быстрый старт

### 1. Сборка и запуск сервера
```bash
# 1. Перейдите в каталог сервера
cd homelan-server

# 2. Скачайте зависимости (требуется libsqlite3-dev для SQLCipher)
go mod tidy

# 3. Инициализируйте USB Master Key на съемный накопитель
go run cmd/server/main.go --init-usb

# 4. Запустите сервер (прослушивает порт 8080)
go run cmd/server/main.go
```

### 2. Запуск тестов
```bash
# Тестирование всех серверных пакетов под race detector
go test -race ./...
```

## ⚠️ Известные ограничения и принятые риски (Accepted Risks)

1. **Отсутствие Perfect Forward Secrecy (PFS):** В силу статического характера ключевых пар X25519, компрометация одного приватного ключа компрометирует всю историю сообщений. Рекомендуется производить регулярную ручную смену ключей в настройках.
2. **Plaintext LAN Transport:** По умолчанию обмен данными в LAN идет по открытому HTTP-протоколу. В недоверенной/незащищенной локальной сети (например, публичный Wi-Fi) злоумышленник может перехватить логины, сессионные токены и метаданные. При необходимости используйте собственные локальные сертификаты TLS.
3. **Локальная база данных клиента:** SQLCipher используется исключительно на стороне сервера. Локальная SQLite база данных на клиентах хранится в открытом виде (но само тело сообщений в ней защищено E2E-шифрованием).
4. **Физический износ Flash-памяти:** Из-за алгоритмов Wear Leveling на SD-картах/SSD, полное стирание секторов на уровне приложения не дает 100% гарантии затирания физических ячеек чипа. Для максимальной надежности сочетайте встроенный Panic Wipe с полнодисковым шифрованием ОС (LUKS).
