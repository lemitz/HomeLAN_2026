HomeLAN — мессенджер ровно для двух человек (например, для вас и вашей второй половинки) и нескольких ваших телефонов и компьютеров. Сервер — небольшая программа на Go, которая работает на одноплатнике у вас дома и хранит переписку; приложения общаются с ним по вашему Wi-Fi, и ничего не выходит за пределы локальной сети.

Серверу доверено как можно меньше. Сообщения и файлы шифруются на устройстве ключами, которых сервер никогда не видит: он хранит только шифротекст и отвергает всё незашифрованное. Его собственная база тоже зашифрована, а ключ от неё лежит на USB-флешке: выдерните флешку — и сервер сотрёт себя. Если сервер подменят или взломают, приложения это заметят: ключ собеседника закрепляется при первом контакте и сверяется по отпечатку.

## Возможности

**Шифрование**
- Сквозное: согласование ключей X25519, HKDF-SHA256, XChaCha20-Poly1305 со случайным 24-байтовым nonce на каждое сообщение
- Отправитель, получатель, тип и id сообщения защищены внутри каждого сообщения: сервер не может подделать сообщение, выдать ваше собственное за ответ собеседника, подменить текст файлом или повторить старое
- Один ключ на человека, хранится в системном хранилище (Android Keystore, Windows DPAPI). Открытым он никуда не передаётся: новое устройство получает его зашифрованным только для себя
- **Отпечатки ключей:** 60 цифр, одинаковых на обоих телефонах. Ключ собеседника закрепляется при первой встрече; если сервер когда-нибудь пришлёт другой, отправка остановится, пока вы не сверите цифры и не примете новый ключ
- При каждом входе приложение сверяет свой ключ с ключом аккаунта на сервере и не продолжит, если они разные

**Переписка**
- Текст, фото и файлы до 2 ГБ. Файлы шифруются по блокам своим ключом и загружаются потоком — большой файл никогда не лежит в памяти целиком
- Галочки «отправлено / доставлено / прочитано», «печатает», удаление у всех, поиск с `*` и `?`, разделители по датам, группировка сообщений
- Ничего не теряется: каждое сообщение ждёт в локальной очереди, пока сервер его не подтвердит, и уходит повторно после переподключения без дублей. Курсор изменений возвращает новые сообщения, отметки о прочтении и удаления после любого времени без связи
- Источник правды — сервер: приложение хранит только кеш шифротекстов, а после переустановки или на новом устройстве вся история скачивается заново
- Картинки расшифровываются по требованию во временную папку, которая чистится при каждом запуске; исполняемые файлы перед открытием требуют подтверждения

**Устройства**
- У каждого до трёх устройств (настраивается). Вход по паролю работает только на уже привязанном устройстве
- **Привязка по двум QR-кодам:** новое устройство показывает QR с одноразовым ключом, старое его сканирует, оба показывают одинаковый 6-значный код сверки, и старое отвечает вторым QR с зашифрованным ключом. Нет камеры на ПК? Оба шага работают через копирование текста
- Список устройств со статусом «в сети» и временем последнего визита; отозванное устройство отключается мгновенно — и по HTTP, и в живом соединении

**Сервер**
- База SQLCipher (AES-256); ключ — файл на USB-флешке, проверяется каждую секунду
- Экстренный вайп при извлечении флешки, по duress-паролю (по желанию), если админ не появлялся заданное число дней (Dead Man's Switch), или по запросу админа с паролем. Вайп уничтожает и ключ на флешке, так что оставшиеся блоки флеш-памяти не прочитать
- Пароли bcrypt, блокировка после серии неудачных попыток, скользящие сессии (хранятся только хеши), квота и срок хранения файлов
- Объявляет себя через mDNS — приложения находят сервер без ввода адреса

**Внешний вид**
- Тёмный интерфейс, плавные анимации: сообщения выезжают, экраны проявляются, галочки меняются на месте
- Запрашивает максимальную частоту экрана (120/144 Гц на Android и Windows); список сообщений перестраивается только когда сообщения действительно меняются
- Русский или английский по языку системы, переключается в настройках

**Защита на устройстве**
- Android: блокировка биометрией или PIN при запуске и при каждом возврате из фона (замок закрывает приложение, не теряя открытый экран), запрет скриншотов и превью в списке недавних, без облачных бэкапов
- Windows: окно исключено из захвата экрана; без связи с сервером переписка скрыта

> Прочитайте [SECURITY.md](SECURITY.md) и [docs/THREAT_MODEL.md](docs/THREAT_MODEL.md), прежде чем доверять HomeLAN что-то серьёзное. Коротко: пока нет Perfect Forward Secrecy, вход и метаданные идут по HTTP внутри сети, а сервер, изъятый вместе со вставленной флешкой, можно расшифровать.

## Как это устроено

```
 Приложение Android / Windows               homelan-server (Orange Pi)
 ┌───────────────────────────┐   Wi-Fi    ┌────────────────────────────────┐
 │ ключ личности (keystore)  │  HTTP +    │ юзеры, устройства, сессии      │
 │ шифрование / расшифровка  │ WebSocket  │ сообщения: только шифротекст   │
 │ очередь + кеш шифротекстов├───────────►│ файлы: зашифрованные блобы     │
 │ закреплённый ключ собесед.│            │ БД SQLCipher ── ключ на USB    │
 └───────────────────────────┘            └────────────────────────────────┘
```

Ключ сообщений: `HKDF-SHA256(X25519(мой, его))`, сообщение: `0x02 | nonce | XChaCha20-Poly1305(текст, aad = отправитель|получатель|тип|id)`. Протокол, синхронизация и привязка устройств описаны в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Управление

| Действие | Как |
|---|---|
| Отправить | `Enter` на ПК (`Shift+Enter` — новая строка), кнопка со стрелкой на телефоне |
| Прикрепить фото или файл | `+` рядом с полем ввода |
| Копировать, отправить снова, удалить | Долгое нажатие на телефоне, правый клик на ПК |
| Открыть фото на весь экран | Нажать; ещё раз — закрыть, щипок — масштаб |
| Поиск по переписке | Лупа в верхней панели |
| Отпечаток ключей, устройства, имя и цвет контакта, настройки | `⋮` в верхней панели |
| Сменить адрес сервера | Нажать на адрес под формой входа |

## Установка

Скачайте со страницы [Releases](https://github.com/lemitz/HomeLAN_2026/releases):

| Файл | Что это |
|---|---|
| `homelan-server-<версия>-linux-arm64.tar.gz` | Сервер для Orange Pi, Raspberry Pi и других 64-битных ARM-плат |
| `homelan-server-<версия>-linux-amd64.tar.gz` | Сервер для Linux x86-64 |
| `homelan-server-<версия>-windows-amd64.zip` | Сервер для Windows |
| `HomeLAN-<версия>-android.apk` | Приложение для Android |
| `HomeLAN-<версия>-windows-x64-setup.exe` | Приложение для Windows, установщик (ставит Visual C++ Runtime при необходимости) |
| `HomeLAN-<версия>-windows-x64.zip` | Приложение для Windows, портативное — папку держите целиком |
| `SHA256SUMS.txt` | Контрольные суммы: `sha256sum -c SHA256SUMS.txt --ignore-missing` или `Get-FileHash <файл> -Algorithm SHA256` в PowerShell |

Файлы не подписаны сертификатом, поэтому Windows SmartScreen может предупредить (*Подробнее* → *Выполнить в любом случае*), а Android попросит разрешить установку из браузера или файлового менеджера. Все APK из релизов подписаны ключом проекта, так что новый релиз ставится поверх старого.

### Сервер

```bash
tar -xzf homelan-server-1.0.0-linux-arm64.tar.gz && cd homelan-server-1.0.0-linux-arm64
./homelan-server --init-usb      # один раз: записывает homelan.key на флешку (существующий ключ не перезаписывает)
./homelan-server                 # находит флешку, открывает базу, слушает :8080
```

Настройки — в `config.yaml` рядом с программой: порт, лимиты пользователей и устройств, размер файлов, квота и срок хранения, Dead Man's Switch, duress-пароль. Сделайте копию `homelan.key` — без него базу не открыть. Unit для systemd и остальная настройка — в [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).

### Первый запуск

1. Откройте приложение. Оно найдёт сервер через mDNS; если нет — нажмите на адрес под формой входа и введите IP сервера.
2. Каждый создаёт аккаунт на своём первом устройстве. Первый аккаунт становится админом.
3. Один раз сверьте отпечатки ключей лично: `⋮` → *Отпечаток ключей* → *Совпадает*. Рядом с именем появится зелёная галочка.
4. Ещё устройства: на новом — *Привязать к аккаунту*, на старом — *Устройства* → *Добавить устройство*.

## Разработка

Нужно:

- Go 1.22+ и C-компилятор для cgo (SQLCipher); на Windows — MinGW-w64
- Flutter 3.38+; для APK — JDK 17 и Android SDK; для Windows — Visual Studio с компонентом *Разработка классических приложений на C++*

```bash
cd homelan-server
go vet ./... && go test -race ./...
go run ./cmd/server --key-file ./dev.key      # только для разработки: ключ из файла вместо флешки

cd client
flutter analyze && flutter test
flutter run -d windows                        # или подключённый телефон
```

Тесты сервера гоняют весь протокол через настоящие HTTP и WebSocket: регистрация, ограничение попыток, duress, привязка, отзыв, сообщения, отметки, синхронизация с удалениями, файлы с Range-запросами, паника и Dead Man's Switch. Тесты клиента покрывают шифрование сообщений (включая порчу, отражение и подмену типа), закрепление ключей, отпечатки, криптографию привязки и шифрование файлов. `client/test/e2e_server_test.dart` гоняет настоящий клиентский код против запущенного сервера:

```bash
HOMELAN_E2E_URL=http://127.0.0.1:8080 flutter test test/e2e_server_test.dart
```

## Релизы

Всё делает [`build.yml`](.github/workflows/build.yml):

- **Pull request в `main`:** `gofmt`, `go vet`, тесты Go с race-детектором, `flutter analyze` и тесты; сервер для linux-amd64, linux-arm64 и windows-amd64, подписанный APK, zip и установщик для Windows прикрепляются к запуску как артефакты. Запуск пишет, выпустит ли мердж релиз.
- **Мердж в `main`:** та же сборка, затем **GitHub Release `v<VERSION>`** со всеми файлами и `SHA256SUMS.txt`; текст — [`RELEASE_NOTES.md`](RELEASE_NOTES.md) плюс список влитых PR. Если такой тег уже есть, ничего не публикуется, так что обычные PR только собираются.
- **Кнопка «Run workflow»:** собирает любую ветку, никогда не публикует.

### Версии

Формат `MAJOR.MINOR.PATCH`:

- **PATCH** (1.0.0 → 1.0.1): только исправления.
- **MINOR** (1.0.0 → 1.1.0): новые возможности, база сервера и протокол остаются совместимыми.
- **MAJOR** (1.x → 2.0.0): изменения, ломающие базу или протокол, нужен чистый старт.

Чтобы выпустить релиз, поднимите версию в [`VERSION`](VERSION), `version:` в `client/pubspec.yaml`, `appVersion` в `client/lib/version.dart` и `Version` в `homelan-server/cmd/server/main.go`, а `RELEASE_NOTES.md` начните с `# HomeLAN v<версия>`. `./scripts/check-release.ps1` проверяет, что всё сходится; workflow тоже его запускает. Мерджите — релиз появится сам.

**Подпись APK.** `./scripts/make-keystore.ps1` создаёт ключ релиза вне репозитория и кладёт его в секреты `HOMELAN_KEYSTORE_BASE64`, `HOMELAN_KEYSTORE_PASSWORD`, `HOMELAN_KEY_ALIAS` и `HOMELAN_KEY_PASSWORD`. Храните копию ключа: если он потеряется, обновить приложение можно будет только через удаление.

## Известные ограничения

- Ровно два человека на сервер — так задумано.
- Нет Perfect Forward Secrecy и автоматической смены ключей: ключи личности постоянные (см. [docs/THREAT_MODEL.md](docs/THREAT_MODEL.md)).
- Транспорт — HTTP внутри сети: содержимое сообщений защищено сквозным шифрованием, пароль при входе и метаданные — нет.
- Нет резервной копии ключа: если человек потеряет все свои устройства, старую переписку прочитать будет нельзя.
- На Windows нет собственной блокировки приложения; переписка скрывается только без связи с сервером.
- Автоудаление сообщений сервер поддерживает, но кнопки в приложениях пока нет.
- Нет сборок для iOS и macOS.
