# Модель угроз HomeLAN Messenger

Документ честно описывает, от чего система защищает и от чего — нет.

## 1. Сводка

| Угроза | Защита | Статус |
|---|---|---|
| Чтение переписки сервером или его владельцем | E2E: X25519 + HKDF + XChaCha20-Poly1305, сервер хранит только шифротекст | ✅ |
| Подмена ключей в LAN (ARP/mDNS-спуфинг, поддельный сервер) | TOFU-закрепление ключа собеседника, сверка отпечатка, проверка своего ключа при входе | ✅ при сверке отпечатка; ⚠️ до сверки первый ключ принимается на доверии |
| Внедрение/подделка сообщений сервером | AEAD + AAD (отправитель, получатель, тип, client_id); незашифрованное содержимое отвергается | ✅ |
| Перехват трафика в LAN | Содержимое E2E. **Пароль при входе, токен и метаданные идут по HTTP** | ⚠️ используйте закрытую Wi-Fi сеть (WPA2/3) |
| Перебор паролей | bcrypt, блокировка IP после 5 неудач на 15 мин, пароль ≥ 8 символов | ✅ |
| Украденное/потерянное устройство | Отзыв устройства: мгновенно отзывает сессии и рвёт соединение | ⚠️ на устройстве остаётся identity-ключ (см. 3.2) |
| Посторонний с доступом к разблокированному телефону | Биометрия/PIN при каждом возврате в приложение, `FLAG_SECURE` | ✅ |
| Скриншоты, превью в «недавних», облачные бэкапы | `FLAG_SECURE`, `allowBackup=false`; Windows — исключение окна из захвата | ✅ |
| Изъятие сервера **вместе с флешкой** (выключили питание) | Нет. Вайп не успевает запуститься, ключ на флешке рядом | ❌ см. 3.1 |
| Изъятие сервера **без флешки** | SQLCipher (AES-256), ключ только на флешке | ✅ |
| Принуждение раскрыть пароль | Duress-пароль (опционально): вайп БД и **ключа на флешке** | ✅ если включён |
| Сервер без присмотра | Dead Man's Switch: вайп, если админ неактивен `timeout_days` | ✅ если включён |
| Форензика SD-карты после вайпа | Уничтожается ключ на флешке → старые блоки БД нечитаемы; файлы вложений зашифрованы E2E | ✅ при вайпе с флешкой на месте |

## 2. Экстренное уничтожение (panic)

Триггеры: извлечение флешки, duress-пароль, Dead Man's Switch, `POST /api/panic`
(админ + пароль).

Порядок: закрыть БД → **затереть и удалить `homelan.key` на флешке** (кроме случая,
когда флешку извлекли — её уже нет) → перезаписать случайными данными и удалить
файл БД, WAL, SHM → удалить файлы вложений → сбросить буферы ФС → завершить процесс.

Главная мера — уничтожение ключа. SQLCipher с raw-ключом не зависит от
заголовка файла, поэтому затирание одних только первых 4 КБ (как было в v0.x)
ничего не давало, пока ключ существует.

Из-за wear leveling на SD/eMMC перезапись файла не гарантирует физического
стирания. Это не важно, если уничтожен ключ, но если вайп сработал по извлечению
флешки — **копия ключа на флешке остаётся у того, кто её забрал**.

## 3. Известные ограничения и принятые риски

### 3.1. Флешка вставлена в сервер
USB-ключ защищает от кражи сервера *без* флешки и даёт вайп при её извлечении.
Если выключить питание, вайп не запустится, а флешка уедет вместе с сервером.
Рекомендации: держите флешку отдельно, когда сервер не нужен; используйте
полнодисковое шифрование ОС (LUKS); физически защитите сервер.

### 3.2. Нет Perfect Forward Secrecy
Identity-ключи статические. Утечка ключа одного пользователя (например, с
украденного устройства) раскрывает всю переписку, если у атакующего есть
шифротексты (копия БД сервера или перехваченный трафик). Отзыв устройства не
меняет ключ. Автоматической смены ключей (rekey) пока нет.

### 3.3. Метаданные видны серверу
Кто, кому, когда, размеры сообщений и файлов, статусы доставки.

### 3.4. HTTP без TLS
Логин, пароль, токен и метаданные передаются открытым текстом внутри LAN.
Содержимое защищено E2E, подмена ключей обнаруживается сверкой отпечатка.

### 3.5. Кеш клиента
Локальная БД клиента не зашифрована дополнительно, но содержит только
шифротексты и метаданные. Токен и ключи — в защищённом хранилище ОС.

### 3.6. Устаревший SQLite в SQLCipher
Драйвер `go-sqlcipher` v4.4.2 встраивает SQLite 3.33 (2020). Сервер не принимает
произвольный SQL, но обновление драйвера — в планах.

### 3.7. Единственное устройство
Если пользователь потерял все свои устройства, identity-ключ потерян и старую
переписку прочитать нельзя. Резервной копии ключа пока нет.
