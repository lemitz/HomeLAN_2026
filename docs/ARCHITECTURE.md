# 🏛️ Архитектура и сетевой протокол (Technical Architecture)

**HomeLAN Messenger v0.5.0 Release Candidate**

---

## 1. Обзор системы
* **Назначение:** Полностью приватный self-hosted мессенджер для домашней локальной сети (LAN) без выхода в интернет и облачных зависимостей.
* **Масштаб:** 2 пользователя, до 4 устройств (например, 2 стационарных ПК на Windows + 2 смартфона на Android).
* **Сервер:** Микрокомпьютер (Orange Pi Zero 3 / Raspberry Pi / x86_64 Linux или Windows), 2GB RAM. Язык — Go 1.21+, база данных — SQLite + SQLCipher (серверная часть полностью зашифрована на диске).
* **Клиенты:** Кроссплатформенное приложение на Flutter (3.16+), база данных — SQLite (`sqflite` на Android, `sqflite_common_ffi` на Windows). Ключи сессии и приватные ключи хранятся в защищенном хранилище платформы (Android Keystore / Windows DPAPI).

## 2. Спецификация сетевых протоколов и авторизация

### 2.1. Авторизация и сессии
В системе реализована полноценная сессионная модель авторизации:
1. При успешной регистрации или входе в систему сервер генерирует криптографически случайный 32-байтовый сессионный токен (кодируемый в 64 символа hex).
2. На сервере сохраняется только **SHA-256 хэш** этого токена.
3. Токен связывается с `user_id`, `device_id`, датой создания и датой окончания действия.
4. Для всех защищенных API-эндпоинтов требуется обязательная передача токена в заголовке `Authorization: Bearer <token>` или `X-Session-Token: <token>`. Токен в query string (`?token=`) **не принимается** — он попадал бы в логи и историю.
5. Использование чужого `device_id` или подмена `user_id` блокируется сервером на уровне сессионной проверки: `user_id` в теле запроса, если передан, обязан совпадать с сессией.
6. Срок жизни сессии — 30 дней; при любом аутентифицированном запросе, когда до истечения осталось меньше 15 дней, сессия продлевается ещё на 30 (sliding expiration). Истёкшие и отозванные сессии удаляются фоновой очисткой через 7 дней.
7. Коды ответов, на которые клиент реагирует особо:
   * `401 Unauthorized` — сессия недействительна/истекла → клиент выполняет «мягкий выход» (сбрасывает токен, **сохраняя** ключи и локальную историю);
   * `403 Forbidden` с текстом `Device revoked` — устройство отозвано → клиент выполняет полную локальную очистку;
   * `409 Conflict` — `device_id` уже занят (повторная регистрация отозванного устройства невозможна);
   * `413 Payload Too Large` / `507 Insufficient Storage` — превышен размер файла / общая квота хранилища;
   * `429 Too Many Requests` + `Retry-After` — ограничение частоты попыток входа/привязки.
8. `POST /api/logout` отзывает текущую сессию и закрывает её активное WebSocket-соединение.

## 3. WebSocket протокол и форматы данных

Для подключения к WebSocket (`/ws?device_id=<id>`) требуется передача сессионного токена в HTTP-заголовке `Authorization: Bearer <token>` (или `X-Session-Token`) при рукопожатии. Параметр `device_id` обязан совпадать с устройством сессии. Политика `Origin` — стандартная same-origin проверка gorilla/websocket (нативные клиенты заголовок `Origin` не отправляют; браузерные страницы с другого origin отклоняются). Одно устройство — одно соединение: новое подключение того же `device_id` закрывает предыдущее.

Все сообщения в канале `/ws` имеют базовую обертку JSON:
```json
{
  "type": "<имя_события>",
  "data": { ... }
}
```

| Клиент → Сервер | Назначение |
|---|---|
| `send_message` | Отправка зашифрованного сообщения. `data.client_id` (UUID) возвращается в `message_sent` для сопоставления с локальной записью |
| `sync` | Догрузка истории: `since_seq_id` (вперёд) или `before_seq_id` (назад), `limit` ≤ 100 |
| `ack`, `read`, `delete` | Подтверждение доставки, прочтения, удаление сообщения |
| `typing`, `ping`, `time_sync` | Индикатор набора, keep-alive, синхронизация времени |

| Сервер → Клиент | Назначение |
|---|---|
| `message_sent` | Эхо отправителю: `seq_id`, `client_id`, `created_at` |
| `new_message` | Новое входящее сообщение |
| `sync_response` | Пачка сообщений, `direction: forward|backward`, флаг `has_more`; удалённые сообщения приходят как tombstone (`is_deleted: true`) |
| `status_update`, `message_deleted`, `user_typing` | Изменения статуса/удаление/набор текста собеседником |
| `time_sync_response`, `pong` | Серверное время |
| `error` | Ошибка с машинным кодом в `data.code` |

Лимиты: размер одного кадра — 64 КБ, неотвеченный ping закрывает соединение.

## 4. Криптографический стек (E2E-Шифрование)

```
[ Отправитель (Alice) ]                                  [ Получатель (Bob) ]
 ├── Private Key (X25519)                                 ├── Private Key (X25519)
 └── Public Key (Bob)                                     └── Public Key (Alice)
       │                                                        │
       ▼                                                        ▼
  Shared Secret (ECDH X25519)                             Shared Secret (ECDH X25519)
       │                                                        │
       ▼                                                        ▼
  Симметричный ключ                                       Симметричный ключ
       │                                                        │
       ├──► ChaCha20-Poly1305 (Шифрование) ──[LAN]──► ChaCha20-Poly1305 (Дешифровка)
```

1. **Асимметричные ключи:** Каждый пользователь имеет долгосрочную пару статических ключей **X25519** (256 бит). Публичные ключи хранятся на сервере.
2. **Алгоритм шифрования:** Сообщения и метаданные файлов шифруются аутентифицированным шифром **ChaCha20-Poly1305** с 96-битным (12 байт) случайным `nonce`.
3. **Хранение на устройстве:** Приватные X25519 ключи и сессионные токены перенесены в защищенное системное хранилище (Android Keystore / Windows DPAPI), обеспечивая надежную изоляцию. База данных SQLite клиента не шифруется, но само содержимое сообщений лежит в ней зашифрованным. Perfect Forward Secrecy (PFS) не поддерживается в связи со статическим характером ключей X25519.

## 5. Алгоритм синхронизации времени (Time Delta Sync)

Микрокомпьютеры (Orange Pi Zero 3) часто не имеют батарейки RTC и без подключения к локальной сети могут сбрасывать время. Алгоритм компенсирует смещение часов клиентов на основе ответов от сервера, содержащих точный `server_time` (Unix Timestamp).

## 6. Защита от OOM при файловом стриминге

1. **Ограничение тела запроса:** Обработчик `/api/files/upload` использует `http.MaxBytesReader` с лимитом `max_file_size_mb` (+1 МБ на служебные заголовки multipart).
2. **Потоковый разбор:** Используется `r.MultipartReader()` — содержимое части `file` пишется напрямую в хранилище (`io.Copy` через `io.LimitReader`), без буферизации всего тела в RAM и без временных файлов.
3. **Квота хранилища:** Перед записью проверяется суммарный размер уже сохранённых вложений против `files.max_size_mb` (`507 Insufficient Storage` при превышении) и наличие свободного места на диске (`utils.HasEnoughSpace`).
4. **Отдача файлов:** `GET /api/files/{id}` использует `http.ServeContent` (поддержка `Range`, корректные заголовки), доступ только для отправителя и получателя файла.
5. **Защита сервера в целом:** `ReadHeaderTimeout`, ограничение размера JSON-тел запросов, лимит кадра WebSocket 64 КБ.

## 7. Клиент: конфигурация сервера и устойчивость

* **Адрес сервера** хранится в настройках клиента (`server_url`). При первом запуске выполняется поиск через mDNS (`_homelan._tcp`), найденный адрес сохраняется. Сохранённый адрес не подменяется автоматически — изменить его можно на экране входа, в **Настройки → Адрес сервера** и на экране «Сервер недоступен» (Windows). Смена адреса применяется ко всем сетевым сервисам без перезапуска.
* **Проверка сессии при старте** различает три исхода: `403` (устройство отозвано → полная очистка), `401` (сессия недействительна → мягкий выход с сохранением ключей и истории), сетевая ошибка (офлайн-режим: локальная история доступна, повторная проверка при восстановлении связи).
* **Выход** (`logout`) завершает сессию на сервере и сбрасывает токен, но сохраняет ключевую пару и локальную историю — после повторного входа переписка остаётся читаемой. **Полная очистка** уничтожает ключи, токен и БД, генерирует новый `device_id` и сохраняет только адрес сервера.
* **Отправка** выполняется только при наличии публичного ключа собеседника; при его отсутствии сообщение не уходит, пользователю показывается ошибка. Входящие сообщения без шифрования помечаются маркером `⚠️ [незашифровано]`.
* **Синхронизация** при подключении догружает историю вперёд пачками до `has_more = false`, обрабатывая tombstone-записи удалённых сообщений.
