# 🏛️ Архитектура и сетевой протокол (Technical Architecture)

**HomeLAN Messenger v0.5.0 Release Candidate**

---

## 1. Обзор системы
* **Назначение:** Полностью приватный self-hosted мессенджер для домашней локальной сети (LAN) без выхода в интернет и облачных зависимостей.
* **Масштаб:** 2 пользователя, до 4 устройств (например, 2 стационарных ПК на Windows + 2 смартфона на Android).
* **Сервер:** Микрокомпьютер (Orange Pi Zero 3 / Raspberry Pi / x86_64 Linux или Windows), 2GB RAM. Язык — Go 1.21+, база данных — SQLite + SQLCipher (серверная часть полностью зашифрована на диске).
* **Клиенты:** Кроссплатформенное приложение на Flutter (3.16+), база данных — SQLite (`sqflite` на Android, `sqflite_common_ffi` на Windows). Ключи сессии и приватные ключи хранятся в защищенном хранилище платформы (Android Keystore / Windows DPAPI).

---

## 2. Спецификация сетевых протоколов и авторизация

### 2.1. Авторизация и сессии
В системе реализована полноценная сессионная модель авторизации:
1. При успешной регистрации или входе в систему сервер генерирует криптографически случайный 32-байтовый сессионный токен (кодируемый в 64 символа hex).
2. На сервере сохраняется только **SHA-256 хэш** этого токена.
3. Токен связывается с `user_id`, `device_id`, датой создания и датой окончания действия.
4. Для всех защищенных API-эндпоинтов требуется обязательная передача токена в заголовке `Authorization: Bearer <token>` или `X-Session-Token: <token>`.
5. Использование чужого `device_id` или подмена `user_id` блокируется сервером на уровне сессионной проверки.

### 2.2. Таблица HTTP-эндпоинтов

## 3. WebSocket протокол и форматы данных

Для подключения к WebSocket (`/ws`) требуется передача сессионного токена (через HTTP-заголовок `Authorization`, subprotocol `Sec-WebSocket-Protocol`, либо в query string `token`). Сервер связывает соединение с `user_id` и `device_id` сессии, запрещая подмену.

Все сообщения в канале `/ws` имеют базовую обертку JSON:
```json
{
  "type": "<имя_события>",
  "data": { ... }
}
```

## 4. Криптографический стек (E2E-Шифрование)

```
[ Отправитель (Alice) ]                                  [ Получатель (Bob) ]
 ├── Private Key (X25519)                                 ├── Private Key (X25519)
 └── Public Key (Bob)                                     └── Public Key (Alice)
       │                                                        │
       ▼                                                        ▼
  Shared Secret (ECDH X25519)                             Shared Secret (ECDH X25519)
       │                                                        │
       ▼                                                        ▼
  Симметричный ключ                                       Симметричный ключ
       │                                                        │
       ├──► ChaCha20-Poly1305 (Шифрование) ──[LAN]──► ChaCha20-Poly1305 (Дешифровка)
```

1. **Асимметричные ключи:** Каждый пользователь имеет долгосрочную пару статических ключей **X25519** (256 бит). Публичные ключи хранятся на сервере.
2. **Алгоритм шифрования:** Сообщения и метаданные файлов шифруются аутентифицированным шифром **ChaCha20-Poly1305** с 96-битным (12 байт) случайным `nonce`.
3. **Хранение на устройстве:** Приватные X25519 ключи и сессионные токены перенесены в защищенное системное хранилище (Android Keystore / Windows DPAPI), обеспечивая надежную изоляцию. База данных SQLite клиента не шифруется, но само содержимое сообщений лежит в ней зашифрованным. Perfect Forward Secrecy (PFS) не поддерживается в связи со статическим характером ключей X25519.

## 5. Алгоритм синхронизации времени (Time Delta Sync)

Микрокомпьютеры (Orange Pi Zero 3) часто не имеют батарейки RTC и без подключения к локальной сети могут сбрасывать время. Алгоритм компенсирует смещение часов клиентов на основе ответов от сервера, содержащих точный `server_time` (Unix Timestamp).

## 6. Защита от OOM при файловом стриминге

1. **Ограничение тела запроса:** Обработчик `/api/files/upload` использует `http.MaxBytesReader(w, r.Body, maxFileSize)`.
2. **Контроль оперативной памяти:** Вызов `r.ParseMultipartForm(32 << 20)` гарантирует, что в RAM осядет не более **32 МБ**, а остальной поток сбрасывается во временные файлы Go.
3. **Прямое копирование:** Данные записываются в хранилище через `io.Copy(dst, io.LimitReader(file, maxFileSize))` без промежуточного чтения всего массива в память (`ReadAll`).
4. **Проверка дискового пространства:** Перед записью выполняется системный вызов `utils.HasEnoughSpace`, требующий наличия свободного места с запасом в 100 МБ.
