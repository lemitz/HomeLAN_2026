# 🚀 Руководство по развертыванию (Deployment Guide)

**HomeLAN Messenger v0.5.0 Release Candidate**

Это практическое пошаговое руководство по настройке и развертыванию HomeLAN Messenger. Мессенджер предназначен для локальной домашней сети на **2 пользователей** и **до 4 устройств** (ПК на Windows и смартфоны на Android). В качестве сервера рекомендуется микрокомпьютер уровня **Orange Pi Zero 3** (2GB RAM) или любой Linux/Windows сервер в LAN.

## 1. Предварительные требования

### Для сервера (Orange Pi Zero 3 / Linux / Windows):
* Свободная USB-флешка (любого объема), которая будет использоваться как аппаратный **USB Master Key**.
* Установленный **Go 1.21+** (если компилируете из исходников) или готовые бинарные файлы из релизов.
* Статический IP-адрес в домашней сети (например, `192.168.1.100`).

### Для клиентов:
* **Android 8.0+** (смартфоны).
* **Windows 10/11** (ПК или ноутбуки).

## 2. Развертывание сервера

### Шаг 2.1. Подготовка директории
Создайте директорию для сервера и скопируйте туда файлы из папки `homelan-server/`:

```bash
sudo mkdir -p /opt/homelan
sudo chown -R $USER:$USER /opt/homelan
cp -r homelan-server/* /opt/homelan/
cd /opt/homelan
```

### Шаг 2.2. Конфигурация (`config.yaml`)
Отредактируйте файл `/opt/homelan/config.yaml` под свои нужды:

```yaml
server:
  host: "0.0.0.0"       # Прослушивать все интерфейсы локальной сети
  port: 8080            # Порт HTTP и WebSocket

database:
  path: "./data/messages.db"

files:
  storage_path: "./data/files"   # Зашифрованные вложения (затираются при вайпе)
  max_size_mb: 2048              # Общая квота хранилища вложений (2 ГБ)
  max_file_size_mb: 100          # Максимальный размер одного файла

security:
  max_users: 2          # Лимит пользователей в системе (по умолчанию 2)
  # Пароль принуждения (Duress Password):
  # Если ввести его на экране входа (с любым именем пользователя), сервер
  # асинхронно запустит вайп данных, а клиенту вернёт обычную ошибку
  # «неверный логин или пароль». Придумайте СВОЮ длинную фразу (минимум
  # 8 символов): сервер отказывается стартовать с коротким значением или
  # с примером из документации.
  duress_password: "CHANGE_ME_TO_A_LONG_UNIQUE_PHRASE"

timeouts:
  read_seconds: 300
  write_seconds: 300
  idle_seconds: 60

dead_man_switch:
  enabled: true         # Включить Dead Man's Switch
  timeout_days: 30      # Дней без активности любого устройства админа до автовайпа
```

> Ограничения, зашитые в сервер (не настраиваются): пароль пользователя 8–72 байта,
> логин 3–32 символа (`A-Za-z0-9_.-`), сообщение до 64 КБ, до 4 устройств на пользователя,
> сессия живёт 30 дней и автоматически продлевается при активности (если осталось
> меньше 15 дней). Защита от перебора пароля: после 5 неудачных попыток для пары
> IP+логин (или 30 с одного IP) сервер отвечает `429 Too Many Requests` с заголовком
> `Retry-After`; задержка растёт экспоненциально от 30 секунд до 15 минут.

## 3. Настройка USB Master Key

Сервер HomeLAN требует постоянного присутствия авторизованной USB-флешки с файлом `homelan.key`. Сервер проверяет наличие флешки **каждую секунду**. Если флешку вытащить — сервер мгновенно запускает экстренное уничтожение БД и файлов.

### Шаг 3.1. Подготовка флешки на Linux (Orange Pi)
1. Вставьте флешку в USB-порт.
2. Проверьте точку монтирования через `lsblk` или `df -h` (например, `/media/user/USB_KEY` или `/mnt/usb`).
3. Запустите генерацию ключа, явно указав точку монтирования флешки:
   ```bash
   chmod +x ./homelan-server-linux-x64
   ./homelan-server-linux-x64 --init-usb --usb /media/user/USB_KEY
   ```
4. Утилита сгенерирует 256-битный криптографический ключ и сохранит его в файл `homelan.key` в корне **указанной** флешки. Если флаг `--usb` не задан, сервер только перечислит найденные съёмные диски и ничего не запишет — так исключается запись ключа на случайный накопитель.

### Шаг 3.2. Подготовка флешки на Windows
1. Вставьте флешку (например, диск `E:`).
2. Запустите консоль от имени администратора в папке с сервером и выполните:
   ```cmd
   homelan-server.exe --init-usb --usb E:\
   ```

> ⚠️ **Важно:** Сделайте бумажную копию ключа (Paper Backup) или сохраните `homelan.key` в надежном офлайн-месте. Без этого ключа запустить зашифрованную БД на сервере невозможно.

## 4. Автозапуск сервера через systemd (Linux)

Для Orange Pi Zero 3 рекомендуется оформить службу `systemd`:

### Шаг 4.1. Отдельный пользователь
Сервер не должен работать от `root`: ему нужны только права на свою директорию данных и чтение флешки.

```bash
sudo useradd --system --home /opt/homelan --shell /usr/sbin/nologin homelan
sudo mkdir -p /opt/homelan/data
sudo chown -R homelan:homelan /opt/homelan
sudo chmod 750 /opt/homelan /opt/homelan/data
```

Проверьте, что пользователь `homelan` может прочитать `homelan.key` на смонтированной флешке (обычно достаточно группы `plugdev`; при автомонтировании через `fstab` используйте опции `uid=homelan,gid=homelan,umask=077`).

### Шаг 4.2. Создание сервиса
Создайте файл `/etc/systemd/system/homelan.service`:

```ini
[Unit]
Description=HomeLAN Messenger Server v0.5.0 RC
After=network-online.target local-fs.target
Wants=network-online.target

[Service]
Type=simple
User=homelan
Group=homelan
SupplementaryGroups=plugdev
WorkingDirectory=/opt/homelan
ExecStart=/opt/homelan/homelan-server-linux-x64 --config /opt/homelan/config.yaml
Restart=always
RestartSec=3
LimitNOFILE=65536
StandardOutput=journal
StandardError=journal

# Hardening: процессу доступна на запись только директория данных
NoNewPrivileges=true
ProtectSystem=strict
ProtectHome=true
ReadWritePaths=/opt/homelan/data
PrivateTmp=true
ProtectKernelTunables=true
ProtectKernelModules=true
ProtectControlGroups=true
RestrictSUIDSGID=true
RestrictRealtime=true
LockPersonality=true
RestrictAddressFamilies=AF_INET AF_INET6 AF_UNIX
CapabilityBoundingSet=
AmbientCapabilities=

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now homelan
sudo journalctl -u homelan -f
```

> Если флешка монтируется в `/media/<user>/...`, добавьте эту точку монтирования в
> `ReadOnlyPaths=` (или убедитесь, что `ProtectHome=true` её не скрывает — `/media` не затрагивается).

## 5. Установка и настройка клиента

### Шаг 5.1. Сборка / Установка клиентов
* **Android:** Перед сборкой release-APK создайте собственный ключ подписи — иначе Gradle подпишет APK общим debug-ключом (предупреждение `WARNING: android/key.properties not found` в логе сборки), и такой пакет сможет «обновить» любой, кто соберёт приложение с тем же `applicationId`:
  ```bash
  keytool -genkey -v -keystore ~/homelan-release.jks -keyalg RSA -keysize 4096 -validity 10000 -alias homelan
  cp client/android/key.properties.example client/android/key.properties   # заполните пути и пароли
  cd client && flutter build apk --release
  ```
  Файлы `key.properties` и `*.jks` находятся в `.gitignore` — не коммитьте их. Скопируйте `build/app/outputs/flutter-apk/app-release.apk` на смартфон и установите. Назначьте приложению права на биометрию, камеру (для QR) и работу в фоне. Версия приложения берётся из `pubspec.yaml`.
* **Windows:** Запустите инсталлятор, собранный через Inno Setup (`homelan_setup.iss`), или запустите `homelan_client.exe` из папки сборки (`flutter build windows --release`).

### Шаг 5.2. Первая регистрация (Создание Админа)
1. Откройте приложение на первом устройстве.
2. При первом запуске клиент ищет сервер в сети через mDNS (`_homelan._tcp`). Текущий адрес показан под заголовком на экране входа — нажмите на него, чтобы ввести адрес вручную (`http://<IP_сервера>:8080`, например `http://192.168.1.100:8080`), найти сервер в сети повторно или проверить соединение. Позже адрес можно изменить в **Настройки → Адрес сервера** (на Windows — также на экране «Сервер недоступен»). Сохранённый адрес больше не подменяется автоматически.
3. Выберите **«Регистрация»**:
   * Введите имя пользователя (3–32 символа, латиница/цифры/`_ . -`, например `Alice`).
   * Введите пароль (минимум 8 символов).
   * При первом входе автоматически создается пара криптографических ключей E2E-шифрования (X25519 / ChaCha20-Poly1305) и криптографически случайный токен сессии.
   * **Первый зарегистрированный пользователь автоматически становится Администратором системы.**
4. Повторите процедуру на втором устройстве для второго пользователя (`Bob`). После регистрации второго пользователя эндпоинт `/api/register` заблокируется (`max_users: 2`).

## 6. Привязка дополнительных устройств

У пользователя может быть до 4 устройств (например, Android-смартфон + стационарный ПК). Чтобы перенести личность и ключи на новое устройство, используется безопасный обмен через **Device Linking**:

```
СТАРОЕ УСТРОЙСТВО (с ключом)                НОВОЕ УСТРОЙСТВО (без ключа)
──────────────────────────────────────────────────────────────────────────
1. Настройки → Устройства → «Добавить»
2. Сервер выдаёт одноразовый код
   (действует 5 минут), экран показывает
   QR-код и кнопку «Копировать код + ключ»
                                      ──►  3. «Привязать к существующему аккаунту»
                                           4a. Отсканируйте QR камерой
                                               ИЛИ
                                           4b. Вставьте текст вида КОД:КЛЮЧ
                                               (если на ПК нет веб-камеры)
                                           5. Готово: ключевая пара импортирована,
                                              устройство получило свой токен сессии.
```

> ⚠️ QR-код и текст «код + ключ» содержат **приватный** ключ шифрования. Передавайте их только напрямую между своими устройствами (не через чаты/облака). Клиент автоматически очищает буфер обмена через 60 секунд после копирования. Привязка без ключа невозможна: все устройства одного пользователя обязаны использовать одну ключевую пару, иначе они перестанут читать переписку друг друга.

## 7. Проверка безопасности и экстренного вайпа

Система имеет несколько эшелонов экстренного уничтожения данных (Panic Wipe):

1. **Аппаратный вайп (Извлечение USB):**
   * Выдерните USB-флешку из сервера.
   * В течение **1 секунды** сервер обнаружит отсутствие ключа (с защитой от ложных срабатываний/дребезга питания через 3 быстрых повтора по 50 мс), закроет БД, **полностью** перезапишет файл БД и `-wal` случайными байтами с `fsync`, удалит их, затрёт заголовки и удалит все вложения, после чего процесс завершится. Повторный запуск вайпа (из второго источника) безопасен — выполняется один раз.
2. **Пароль принуждения (Duress Password):**
   * Если злоумышленник требует пароль от входа на клиенте, введите `duress_password` из `config.yaml` с любым именем пользователя.
   * Сервер ответит клиенту обычной ошибкой «неверный логин или пароль» (с той же задержкой, что и настоящая проверка), но в фоне запустит полное уничтожение всех данных.
3. **Dead Man's Switch (Таймер неактивности):**
   * Если ни одно устройство администратора не проявляло активности (вход, WebSocket-соединение, запросы к API) более `timeout_days` (по умолчанию 30 дней), фоновый монитор сервера автоматически вызовет экстренный вайп. Переключатель `dead_man_switch.enabled: false` полностью отключает механизм. Проверка выполняется раз в час, первая — через час после старта процесса: после включения сервера у администратора всегда есть минимум час, чтобы войти с любого устройства. Резкий скачок системных часов вперёд между проверками (ручная установка даты, первая NTP-синхронизация на Orange Pi без RTC) пропускает текущую проверку, а при явно неверном времени (год < 2024) проверка не выполняется вовсе.
4. **Защищенный вызов Panic по API:**
   * Отправьте POST-запрос с подтверждением и валидным токеном администратора:
     ```bash
     curl -X POST http://192.168.1.100:8080/api/panic \
          -H "Authorization: Bearer <ADMIN_SESSION_TOKEN>" \
          -H "Content-Type: application/json" \
          -d '{"confirm":"DESTROY_ALL_DATA"}'
     ```
