# 🚀 Руководство по развертыванию (Deployment Guide)

**HomeLAN Messenger v2.3 FINAL**

Это практическое пошаговое руководство «как всё развернуть и не свихнуться». Мессенджер предназначен для локальной домашней сети на **2 пользователей** и **до 4 устройств** (ПК на Windows и смартфоны на Android). В качестве сервера рекомендуется микрокомпьютер уровня **Orange Pi Zero 3** (2GB RAM) или любой Linux/Windows сервер в LAN.

## 1. Предварительные требования

### Для сервера (Orange Pi Zero 3 / Linux / Windows):
* Свободная USB-флешка (любого объема), которая будет использоваться как аппаратный **USB Master Key**.
* Установленный **Go 1.21+** (если компилируете из исходников) или готовые бинарные файлы из репозитория:
  * `homelan-server-arm64` — для Orange Pi / Raspberry Pi 4/5 (ARM64)
  * `homelan-server-linux-x64` — для обычных Linux-серверов x86_64
  * `homelan-server.exe` — для Windows-сервера
* Статический IP-адрес в домашней сети (например, `192.168.1.100`).

### Для клиентов:
* **Android 8.0+** (смартфоны).
* **Windows 10/11** (ПК или ноутбуки).

## 2. Развертывание сервера

### Шаг 2.1. Подготовка директории
Создайте директорию для сервера и скопируйте туда файлы из папки `homelan-server/`:

```bash
sudo mkdir -p /opt/homelan
sudo chown -R $USER:$USER /opt/homelan
cp -r homelan-server/* /opt/homelan/
cd /opt/homelan
```

### Шаг 2.2. Конфигурация (`config.yaml`)
Отредактируйте файл `/opt/homelan/config.yaml` под свои нужды:

```yaml
server:
  host: "0.0.0.0"       # Прослушивать все интерфейсы локальной сети
  port: 8080            # Порт HTTP и WebSocket

database:
  path: "./data/messages.db"

files:
  storage_path: "./data/files"
  max_size_mb: 2048     # Лимит хранилища файлов (2 ГБ)

security:
  max_users: 2          # Лимит пользователей в системе (по умолчанию 2)
  # Пароль принуждения (Duress Password):
  # Если ввести его при авторизации, сервер асинхронно запустит вайп данных,
  # а клиенту вернёт ошибку неверного пароля (чтобы скрыть удаление).
  duress_password: "panic123"

timeouts:
  read_seconds: 300
  write_seconds: 300
  idle_seconds: 60

dead_man_switch:
  enabled: true         # Включить Dead Man's Switch
  timeout_days: 30      # Количество дней отсутствия админа до автовайпа
```

## 3. Настройка USB Master Key

Сервер HomeLAN требует постоянного присутствия авторизованной USB-флешки с файлом `homelan.key`. Сервер проверяет наличие флешки **каждые 5 секунд**. Если флешку вытащить — сервер мгновенно запускает экстренное уничтожение БД и файлов.

### Шаг 3.1. Подготовка флешки на Linux (Orange Pi)
1. Вставьте флешку в USB-порт.
2. Проверьте точку монтирования через `lsblk` или `df -h` (например, `/media/user/USB_KEY` или `/mnt/usb`).
3. Запустите генерацию ключа:
   ```bash
   # Если используете готовый бинарник (ARM64):
   chmod +x ./homelan-server-arm64
   ./homelan-server-arm64 --init-usb
   ```
4. Утилита автоматически найдет съемный диск, сгенерирует 256-битный криптографический ключ и сохранит его в файл `homelan.key` в корне флешки.

### Шаг 3.2. Подготовка флешки на Windows
1. Вставьте флешку (например, диск `E:`).
2. Запустите консоль от имени администратора в папке с сервером и выполните:
   ```cmd
   homelan-server.exe --init-usb
   ```

> ⚠️ **Важно:** Сделайте бумажную копию ключа (Paper Backup) или сохраните `homelan.key` в надежном офлайн-месте. Без этого ключа запустить зашифрованную БД на сервере невозможно.

## 4. Автозапуск сервера через systemd (Linux)

Для Orange Pi Zero 3 рекомендуется оформить службу `systemd`:

### Шаг 4.1. Создание сервиса
Создайте файл `/etc/systemd/system/homelan.service`:

```ini
[Unit]
Description=HomeLAN Messenger Server v2.3
After=network.target local-fs.target
Wants=network-online.target

[Service]
Type=simple
User=root
WorkingDirectory=/opt/homelan
ExecStart=/opt/homelan/homelan-server-arm64
Restart=always
RestartSec=3
LimitNOFILE=65536
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```

### Шаг 4.2. Активация службы
```bash
sudo systemctl daemon-reload
sudo systemctl enable homelan.service
sudo systemctl start homelan.service
```

### Шаг 4.3. Проверка статуса и логов
```bash
sudo systemctl status homelan.service
sudo journalctl -u homelan.service -f
```
В логах вы должны увидеть сообщения:
* `🔧 USB Master Key Setup` — ключ найден на флешке
* `🔒 Database encrypted with SQLCipher` — база успешно открыта
* `📡 mDNS service started` — служба автообнаружения в сети работает

## 5. Установка и настройка клиента

### Шаг 5.1. Сборка / Установка клиентов
* **Android:** Скопируйте собранный APK (`app-release.apk`) на смартфон и установите. Назначьте приложению права на биометрию и работу в фоне.
* **Windows:** Запустите инсталлятор, собранный через Inno Setup (`homelan_setup.iss`), или запустите `homelan_client.exe` из папки сборки.

### Шаг 5.2. Первая регистрация (Создание Админа)
1. Откройте приложение на первом устройстве.
2. В поле **Адрес сервера** укажите `http://<IP_сервера>:8080` (например, `http://192.168.1.100:8080`).
3. Выберите **«Регистрация»**:
   * Введите имя пользователя (например, `Alice`).
   * Введите пароль.
   * При первом входе автоматически создается пара криптографических ключей E2E-шифрования (X25519 / XChaCha20-Poly1305).
   * **Первый зарегистрированный пользователь автоматически становится Администратором системы.**
4. Повторите процедуру на втором устройстве для второго пользователя (`Bob`). После регистрации второго пользователя эндпоинт `/api/register` заблокируется (`max_users: 2`).

## 6. Привязка дополнительных устройств

У пользователя может быть до 2 устройств (например, Android-смартфон + стационарный ПК). Чтобы перенести личность и ключи на новое устройство, используется безопасный обмен через **Device Linking**:

```
НОВОЕ УСТРОЙСТВО (Без ключа)       СТАРОЕ УСТРОЙСТВО (С ключом)
───────────────────────────────────────────────────────────────
1. Нажмите "Привязать устройство"
2. Экран покажет QR #1 (эфеме-   ──► 3. Откройте Настройки -> Привязать
   мерный публичный ключ)             4. Отсканируйте QR #1
                                      5. Старое устройство зашифрует identity-ключ
                                      6. Появится QR #2 и Текстовый код
                                 ◄──
7a. Отсканируйте QR #2 камерой
    ИЛИ
7b. Вставьте текст (Text Fallback),
    если на ПК нет веб-камеры!
8. Готово! Ключи импортированы, устройство привязано к серверу.
```

### Инструкция для стационарного ПК без камеры (Text Fallback):
1. На ПК выберите **«Привязать устройство»**.
2. Поскольку камеры нет, нажмите кнопку **«Скопировать код QR #1»** и отправьте его на телефон (или перепишите текстовую строку).
3. На телефоне вставьте код в поле ручного ввода — телефон сгенерирует зашифрованную строку ответа.
4. Скопируйте строку ответа с телефона в поле ввода на ПК. Привязка завершится мгновенно без использования камеры.

## 7. Проверка безопасности и экстренного вайпа

Система имеет несколько эшелонов экстренного уничтожения данных (Panic Wipe):

1. **Аппаратный вайп (Извлечение USB):**
   * Выдерните USB-флешку из сервера.
   * В течение **5 секунд** сервер обнаружит отсутствие ключа, закроет БД, перезапишет первые 4 КБ файла БД (заголовок SQLCipher) случайными байтами `urandom`, удалит файлы `-wal`/`-shm` и вложения, после чего процесс завершится.
2. **Пароль принуждения (Duress Password):**
   * Если злоумышленник требует пароль от входа на клиенте, введите `duress_password` из `config.yaml` (например, `panic123`).
   * Сервер ответит клиенту `Invalid credentials`, но в фоне запустит полное уничтожение всех данных.
3. **Dead Man's Switch (Таймер неактивности):**
   * Если администратор не заходил в систему более `timeout_days` (по умолчанию 30 дней), фоновый монитор сервера автоматически вызовет экстренный вайп.
4. **Ручной вызов по API:**
   * Отправьте POST-запрос с подтверждением:
     ```bash
     curl -X POST http://192.168.1.100:8080/api/panic \
          -H "Content-Type: application/json" \
          -d '{"confirm":"DESTROY_ALL_DATA"}'
     ```
